## Executive summary

The strategy is sharp and the design system is genuinely excellent — on paper. The
clunkiness users feel isn't a styling problem. It's that the product makes them
**work**: to set up, to decode cold language, and to trust that anything they did
actually saved.

- **Reviewed:** live app + repo
- **Lens:** our own docs (`PRODUCT_STRATEGY`, `PRODUCT_DESIGN`)
- **Root causes:** five
- **Focus:** mobile-first

## The one idea

> **Curio asks users to behave like archivists before it ever lets them feel like
> collectors.**

Every clunky moment users report — "confusing," "too much effort to set up," "feels
broken" — traces back to that inversion. The fix is not more features or a fresh
coat of paint. It's **resequencing the product so delight comes first and the
bookkeeping comes later**, exactly as our own Product Design doc already prescribes.
Much of this review is simply: _ship what you already decided to build._

## 01 — From complaint to cause

Each thing users actually said, traced to what's structurally happening in the UI,
checked against the principle it violates. The complaints cluster into five root
causes.

| What users say                | What's actually happening                                                                                                                                        | Principle it breaks                                   |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| _"Too much effort to set up"_ | Creating a collection drops you into a field-builder; adding an item shows a long form before any reward. Schema work comes before the first photo.              | "5-minute time-to-value"; "Identity before inventory" |
| _"Confusing / complex"_       | The Home screen stacks up to six competing blocks (two CTA banners can show at once). The profile menu is a grab-bag of account, theme, legal, import, sign-out. | "Single-path first run"; "Defer distractions"         |
| _"Feels broken"_              | Save / sync state lives in a small header badge and a transient toast. When feedback is ambiguous or missed, users assume failure even when it worked.           | "Trust is the first product job"                      |
| _"Print doesn't work"_        | Print fires `window.print()` and relies on an `@media print` visibility hack with conflicting widths (80mm vs 100mm) and no preview. Brittle across browsers.    | "Reliable add and edit flows"; trust                  |
| _(unspoken) "It feels cold"_  | UI copy says Artifacts, Archives, "Restoring archives…", "New Archive", "Archival Record" — the exact institutional words our voice guide tells us to avoid.     | "Beauty before bureaucracy"; voice & tone table       |

---

## 02 — The five root causes (fix in this order)

1. **The setup tax.** Users hit schema decisions (collections, fields, templates)
   before they ever capture one meaningful object. The reward is gated behind
   bookkeeping. Let the first photo come first; defer structure until there's
   something to structure.
2. **Trust is invisible.** "Did it save?" is the most expensive question in the app,
   because the answer is whispered in a 12px badge and a toast that disappears. Make
   state loud, persistent, and attached to the object — a museum people don't trust
   is just anxiety with nice fonts.
3. **Everything-at-once screens.** Home competes with itself (two banners, bento,
   On-This-Day, floating search, grid). The add form shows every field up front. One
   primary action per screen; collapse advanced detail behind a quiet "More" rather
   than presenting it as homework.
4. **Cold vocabulary.** "Artifact," "Archive," "Archival Record," "Restoring
   archives…" read like a cataloguing system, not a personal museum. The voice guide
   already says avoid this. Speak like a thoughtful friend, not a registrar.
5. **Brittle edges (print & co.).** A few features work in theory but fail in real
   browsers (print is the clearest case). Each silent failure compounds the "is this
   broken?" feeling. Either make a feature reliable or remove it — a half-working
   button costs more trust than a missing one.

## 03 — The worst offenders, redesigned

Low-fidelity mobile wireframes — structure and sequence, not final pixels. The point
is what's on each screen and in what order.

### A. First run & Home

**Now:** a brand-new user lands on a screen carrying two CTA banners, an onboarding
checklist, a bento hero with stats, On-This-Day, a floating search bar, and a grid —
before they've done anything.

- ✕ Two banners + checklist before any value
- ✕ Search bar overlaps the hero with a negative margin (fragile)
- ✕ Stats read "Artifacts / Archives"

**Proposed · first run:** one screen, one decision.

- Hero: _"Start your museum with one thing you love."_
- Sub: "A ticket stub, a tea tin, a record. We'll handle the rest."
- Primary: **＋ Add your first piece**
- Secondary: **✦ Wander a sample museum**
- Footer: "No account needed to look around" — sign-in only when they save.

**Proposed · once it has content:** the rich Home (Your museum, search, On This Day,
collections grid) is **earned, not the front door**. Add is always reachable
bottom-center.

### B. Add an item

Our own doc already specifies the simple version: **photo → title → a couple of key
fields → story → rating → save**, with "More details" collapsed and AI filling in
place. The redesign is mostly shipping that spec and making the photo the hero, not
the form.

**Now:**

- ✕ A wall of fields; photo is just one row
- ✕ Story competes with metadata for attention
- ✕ Save can scroll off-screen

**Proposed:** Photo first → AI fills quietly ("✦ Curio is reading this…", suggested
chips like _Brand / Year / Origin_) → story is the hero ("Your story — Where did you
find it? Why does it matter?") → rating → **Save to your museum** is always pinned.
Metadata hides under "More details."

### C. Create a collection

The single biggest source of "too much effort to set up." A field-builder is a
database tool, and it's the first thing a collector meets.

**Now:**

- ✕ Schema design as step one
- ✕ No idea what a "field" should be yet

**Proposed · ask first:** lead with one human question — _"What do you collect?"_ —
with a free-text input ("e.g. loose-leaf teas…") **or start from a shelf**: presets
for the beachhead categories (Tea & coffee, Vinyl, Wine & spirits, Tickets).

**Proposed · confirm fields:** _"For teas, most people track…"_ — Curio proposes,
the user confirms (tap to keep). Defaults to **1–2 pinned fields** (e.g. Origin,
Type), others optional, "＋ Add your own" available. CTA: **Create & add first
piece.**

### D. "Is it broken?" — trust & the print bug

Two things make a working app feel broken: invisible save/sync state, and features
that silently fail.

**Feedback — now:** status is a 12px header dot + a toast that vanishes; miss the
toast → assume it failed.

**Feedback — proposed:** state lives **on the item** (a quiet "✓ Saved & backed up"
badge), and the confirmation says what actually happened, in plain words — "Saved to
your museum" / "Backed up to the cloud just now."

**The print bug, specifically:** the Export sheet's Print button calls
`window.print()` then hides the entire app with an `@media print` visibility hack,
fixed-positioning a single `#card-preview` node. The card's width is set three ways
that fight each other — inline `min(85vw, 560px)`, Tailwind `print:!w-[100mm]`, and
CSS `width:80mm !important`. No preview, no feedback → blank or clipped page → "print
is broken."

> **Recommendation:** We already render a pixel-perfect PNG of the card
> (`html-to-image`) for Save & Share. Make **"Save image"** the primary way to get a
> copy, and **demote Print**. If print stays, open the PNG in a clean print document
> (one image, one width unit) instead of CSS-hiding the live app — deterministic
> across every browser.

## 04 — Warm the words

The voice guide already names the target: "a thoughtful friend who appreciates
meaningful objects." The shipped strings drifted toward registrar. A find-and-replace
pass is one of the highest-leverage hours we can spend — it changes the whole
emotional register at near-zero cost.

| Where               | Now                             | Warmer                   |
| ------------------- | ------------------------------- | ------------------------ |
| Home stats          | Artifacts · Archives            | **Pieces · Collections** |
| Loading             | Restoring archives…             | **Opening your museum…** |
| New collection tile | New Archive · Expand your space | **Start a collection**   |
| Hero label          | Featured Artifact               | **In the spotlight**     |
| Export card footer  | Archival Record                 | **From my museum**       |
| Save confirmation   | Saved · syncing                 | **Saved & backed up**    |

> Keep the monospace accession labels — they're a deliberate, lovely design risk. The
> fix is the _words_, not the typeface.

## 05 — What "good" looks like

The same redesigns, rendered in Curio's real design system — DM Serif Display, Inter,
JetBrains Mono accession labels, the warm amber/stone palette, the mat-and-frame card
metaphor. (See the HTML artefact for the fully-dressed hi-fi mockups.)

- **Home · Gallery theme:** "Welcome back / Your museum," search, an On-This-Day hero
  card, a collections grid, and a 5-slot bottom nav — **Home · Explore · ＋ (center
  FAB) · Wrapped · You**.
- **Add a piece · photo-first:** large photo hero with a "Curio is reading this…"
  chip, name field, suggested _Origin / Type_ chips, "Your story" prompt, rating, and
  a pinned **Save to your museum**.

## 06 — Where to start (a sequence, not a backlog)

Ordered by trust-per-hour. The first column is mostly copy and small UI moves
shippable this week; value compounds as you move right.

**Quick wins · hours–1 day — stop the bleeding**

- Warm the vocabulary (string find-and-replace per §04). _(RC4)_
- Loud, plain save confirmation — "Saved & backed up," persistent badge on the item. _(RC2)_
- Demote Print, promote Save image — make the working PNG the primary copy action. _(RC5)_
- Never show two banners at once — one CTA on Home; drop the negative-margin search overlap. _(RC3)_

**This sprint · days — reshape the flows**

- Single-action first run — empty state = "Add your first piece" + sample. _(RC1·RC3)_
- Photo-first add form — story up, metadata behind "More details," sticky Save. _(RC1·RC3)_
- "What do you collect?" first — presets + suggested fields before any field-builder. _(RC1)_
- Split the profile grab-bag — theme picker out of the account menu into its own quick toggle. _(RC3)_

**Bigger bets · weeks — deepen the moat**

- Story prompts that feel alive — AI suggests questions; user always writes the answer. The moat. _(Strategy §5)_
- Public museum profile — editorial, opt-in, shareable — the Phase 1 core loop. _(Phase 1)_
- Collection Wrapped — the first intentionally viral surface; depth, not streaks. _(Phase 1)_

---

## The honest summary

> You don't have a design problem so much as a sequencing problem. Put delight before
> bookkeeping, make trust visible, and warm the words — and Curio will finally feel
> like the museum it already is on paper.
